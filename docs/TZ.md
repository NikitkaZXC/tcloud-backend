# tcloud — техническое задание

Облачное хранилище медиа поверх Telegram с REST API.
Ролей и мультипользовательности в текущей версии нет.

## 1. Суть

- Медиа выгружается через **Telethon** (MTProto, пользовательский аккаунт) в приватные
  каналы Telegram — **хранилища**.
- У каждого файла есть **UUID**, который связывает его с произвольным путём, как в сокращателе ссылок:
  `tcloud/{uuid хранилища}/{папки пользователя}/{имя файла}`, например
  `tcloud/3f2a9c1e-…/отпуск/2026/photo.jpg`.
- `file_id` Telegram меняется (`file_reference` протухает), поэтому его **не храним**.
  Храним `tg_chat_id` + `message_id`, а сообщение при необходимости запрашиваем заново.
- UUID пишется в подпись к сообщению. По нему файл ищется внутренним поиском Telegram
  (`messages.search`). Поиск по числовому id давал бы ложные совпадения, а UUID уникален.

## 2. Telegram-аккаунт

- Нужен **пользовательский аккаунт**, не бот: бот не может создавать каналы и не имеет Premium.
- Вход: `make login` — интерактивно (телефон, код, 2FA),
  сессия сохраняется в docker volume. Файл сессии = пароль от аккаунта, в git не попадает.
- Premium определяется автоматически (`get_me().premium`) при старте и перед каждой загрузкой
  (подписка могла кончиться).

## 3. Лимиты Telegram

Все лимиты собраны в одном модуле конфигурации, а не разбросаны по коду.

| Что | Без Premium | С Premium | Как учитываем |
|---|---|---|---|
| Размер файла (документ, видео, аудио) | 2 ГБ | 4 ГБ | Проверка до загрузки (по заявленному размеру) и во время приёма (по факту). Превышение → `413` |
| Фото, отправленное как фото (`send_as=media`) | 10 МБ, сумма сторон ≤ 10000, соотношение ≤ 1:20 | то же | Если не проходит — отправляем документом, в ответе `sent_as: "file"` и `warning` |
| Подпись к сообщению | 1024 символа | 2048 | В подписи только токен UUID, путь хранится в БД |
| Превью видео | JPEG ≤ 200 КБ, сторона ≤ 320 px | то же | Генерируем ffmpeg с этими ограничениями |
| Название канала | 128 символов | то же | Валидация → `422` |
| Описание канала | 255 символов | то же | Валидация → `422` |
| Каналов на аккаунт | 500 | 1000 | Ошибка TG `CHANNELS_TOO_MUCH` → `409` с понятным текстом |
| Удаление / получение сообщений | 100 за запрос | то же | Пакетная обработка |
| FloodWait | — | — | Ждём `retry_after` и повторяем, если ожидание ≤ 60 с. Иначе задача `failed` с `retry_after` |
| Частота запросов | — | — | Не больше 2 одновременных выгрузок в TG (настраивается). Массовые действия идут с паузами — защита от бана аккаунта |

## 4. Хранилища

Хранилище — приватный **канал** Telegram (broadcast), без username и без инвайт-ссылок.
Доступ есть только у владельца. Выдать доступ другому пользователю или боту владелец
может сам через Telegram, это вне зоны ответственности проекта.

**В БД храним только** `id` (наш UUID), `tg_chat_id` и даты. Название, описание и фото
живут в Telegram и подтягиваются оттуда:

- **название** = title канала, задаётся при создании, можно менять;
- **описание** = about канала, можно задать и менять;
- **фото** = аватар канала, можно поставить или убрать; отдаётся потоком из TG и у нас не сохраняется.

Список хранилищ: id из БД + метаданные из Telegram (`channels.getFullChannel` на каждый канал —
описание есть только в полной информации о канале; FloodWait до 60 с Telethon пережидает сам).
Если канал больше недоступен (удалён или нас выгнали), хранилище в ответе помечено `available: false`.

Инициализация из `.env`: `TELEGRAM_CHATS=-1001234567890,-1009876543210` — **только id существующих каналов**.
- При старте каждый id подключается как хранилище, если его ещё нет в БД (повторный запуск ничего не дублирует).
- Перед подключением проверяем: у канала нет username, мы админ с правом удалять сообщения.
  Иначе — ошибка в лог, канал не подключается.
- Пусто → ничего не делаем.

## 5. Файлы и папки

- Медиа: фото (jpg, png, webp, heic, статичный gif), видео (mp4, mov, webm, mkv),
  аудио (mp3, m4a, ogg, flac, wav), GIF-анимации. Остальные файлы — документы (`kind = document`), кроме
  исполняемых, скриптов и установщиков (по имени, по содержимому и внутри zip) → `415 blocked_file_type`.
- Тип определяется **по содержимому** (magic bytes), а не по расширению или `Content-Type`.
  Затем файл проверяется декодером (Pillow для фото, ffprobe для видео и аудио).
  Расширение в имени должно соответствовать реальному типу.
- **Папки хранятся только в БД**, в Telegram уходят только файлы. Папку можно создать пустой.
  Удаление папки — рекурсивное: удаляются все файлы из TG пачками по 100, затем записи из БД.
- **Удаление** только через API: удаляется сообщение в TG и запись в БД.
  Ручные удаления в Telegram БД не отслеживает.
- **Способ отправки** `send_as`:
  - `file` (по умолчанию) — документ, оригинал без изменений.
  - `media` — фото сжато Telegram'ом; видео в оригинале, с атрибутами и плеером; аудио с плеером; GIF как анимация.
    Фото в webp/heic/gif перед отправкой переводятся в JPEG (Telegram принимает как фото только JPEG/PNG).
    Для сжатого фото `size`, `width`, `height` в БД — того, что хранит Telegram; `sha256` — всегда от оригинала.
- **Видео не перекодируем** (Telegram не пережимает видео, загруженное через API).
  Бэкенд через ffprobe считает ширину, высоту, длительность, поворот (rotation) и передаёт в
  `DocumentAttributeVideo(w, h, duration, supports_streaming=True)` — иначе соотношение сторон «поплывёт».
  Встроенный плеер TG надёжно работает с MP4 (H.264/H.265 + AAC). Другие контейнеры могут
  отображаться файлом, в ответе тогда будет `warning`.
- Аудио: длительность, исполнитель и название из тегов → `DocumentAttributeAudio`.
- **Конфликт путей** — как в проводнике, параметр `on_conflict`:
  `error` (по умолчанию, `409`) · `replace` (старое сообщение удаляется, UUID сохраняется, `updated_at` обновляется) ·
  `keep_both` (`photo (1).jpg`) · `skip`. Папки при совпадении объединяются.
- **Правила пути:** сегменты разделены `/`. Запрещены пустые сегменты, `.` и `..`, управляющие символы,
  `\`. Сегмент ≤ 255 байт, весь путь ≤ 1024 символов. Unicode нормализуется в NFC, регистр учитывается.

## 6. Загрузка

### С устройства

1. `POST /api/uploads?path=&send_as=&on_conflict=&priority=&callback_url=`, тело — файл потоком, размер из
   `Content-Length`. Проверки до чтения тела: если размер больше лимита аккаунта, сразу `413`.
2. Файл пишется во временный файл на общем томе с проверкой лимита на лету, задача ставится в очередь, ответ `202`
   с `task_id`. Затем воркеры: проверки (§8), отправка в TG, удаление временного файла в любом исходе.

Прямой стрим в TG без диска невозможен: до отправки надо проверить тип и вирусы, а для видео — посчитать атрибуты.

### По ссылке

`POST /api/uploads/from-url` с параметрами: `url`, путь с **собственным именем файла**
(не обязательно как в интернете), `send_as`, `on_conflict`, `priority`, `callback_url`. Скачивает воркер.
- До скачивания делаем HEAD/первые байты: проверяем `Content-Length` против лимита и тип по magic bytes.
  Если исполняемый файл — обрываем сразу.
- Дальше та же цепочка: скачать → проверки → TG → удалить.

## 7. Прогресс

Задача (`task`): статус `queued → running → done | failed`, стадии `downloading` (только по URL) → `scanning` → `uploading_tg` → `done`.
По каждой стадии видны: процент, байты, скорость, ETA, ошибка.

- **Пулинг:** `GET /tasks/{id}`.
- **Вебхук (опционально):** если задан `callback_url`, шлём POST при смене стадии и не чаще
  раза в 2 с с прогрессом. Подпись `X-Tcloud-Signature` (HMAC-SHA256 от тела). 3 повтора с backoff.
  `callback_url` проходит ту же SSRF-проверку, что и ссылки на файлы.
- Задачи живут в RabbitMQ и Redis и переживают рестарт API; упавший воркер получает задачу снова.

## 8. Безопасность

Файлы **никогда не исполняются и не открываются ничем, кроме декодеров-валидаторов.**

- **Доступ:** один `X-API-Key` из `.env`, сравнение в постоянном времени. По умолчанию сервер
  слушает только `127.0.0.1`.
- **Тип файла:** по magic bytes; медиа валидируется декодером, исполняемое содержимое запрещено. Pillow с лимитом пикселей
  против decompression bomb. ffprobe в subprocess без `shell`, с таймаутом.
- **Антивирус:** ClamAV (отдельный контейнер `clamav/clamav:*-debian` — он есть и под arm64), скан через `clamd INSTREAM`.
  Лимиты потока подняты до 4000 МБ в `docker/clamd.conf` (по умолчанию clamd режет на 100 МБ).
  Включены строгие проверки (зашифрованное, макросы, превышение лимитов, PUA). Заражён → `422 infected`,
  не проверить до конца → `422 unscannable` (обход: `allow_unscannable=true`, вирусы всё равно отклоняются).
  ClamAV недоступен → загрузка отклоняется (fail-closed).
- **Ссылки (SSRF):** только `http`/`https`. DNS резолвится и запрещаются loopback, private,
  link-local, multicast, адреса метаданных облака, IPv6-аналоги. Соединяемся с проверенным IP.
  Не больше 5 редиректов, каждый проверяется заново. Таймауты на соединение и чтение,
  жёсткий лимит размера при чтении.
- **Временные файлы:** случайные имена в отдельной папке, права 0600, удаляются в `finally`.
  Имя от пользователя в файловой системе не используется.
- **Docker:** приложение под non-root, read-only rootfs (кроме tmp и сессии), Postgres и ClamAV
  наружу не публикуются.
- **Секреты:** `.env` и файл сессии не коммитятся. Зависимости с зафиксированными версиями, `pip-audit` в тестах.
- Данные в каналах пока **не зашифрованы**, поэтому приватность каналов критична (§4).

## 9. Стек и запуск

- Python 3.14 (uv), FastAPI, loguru, Telethon, SQLAlchemy 2 (async) + asyncpg, Alembic, httpx,
  Pillow + pillow-heif, ffmpeg/ffprobe, clamd.
- **Всё запускается через Docker Compose:** `app`, `postgres:16`, `clamav`.
  Volumes: данные Postgres, сессия Telethon, временные файлы.
- `make up` — запуск (`docker-compose.prod.yml`); миграции Alembic применяются при старте контейнера.

## 10. База данных (PostgreSQL)

| Таблица | Поля | Индексы |
|---|---|---|
| `storages` | `id uuid PK`, `tg_chat_id bigint`, `created_at`, `updated_at` | `UNIQUE(tg_chat_id)` |
| `folders` | `id uuid PK`, `storage_id FK`, `path text`, `created_at`, `updated_at` | `UNIQUE(storage_id, path)`; `path text_pattern_ops` для поиска по префиксу |
| `files` | `id uuid PK`, `storage_id FK`, `folder_path text`, `name text`, `size bigint`, `mime`, `kind` (photo/video/audio/animation), `sent_as`, `width`, `height`, `duration`, `sha256`, `tg_message_id bigint`, `created_at`, `updated_at` | `UNIQUE(storage_id, folder_path, name)`; `(storage_id, folder_path)` для листинга; `UNIQUE(storage_id, tg_message_id)`; `sha256` |
Задачи загрузки в БД не хранятся: статус и прогресс — в Redis (7 дней), очередь — RabbitMQ.

- **Все наши id — UUID** (`uuid4`, генерируется на сервере). Числа (`tg_chat_id`, `tg_message_id`) — только id самого Telegram.
- Каждый новый запрос с фильтром/сортировкой обязан иметь индекс.

## 11. API

Все ручки живут под `/api` и требуют `X-API-Key`. Swagger: `/docs`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/health` | жив ли сервис, есть ли связь с TG, БД, ClamAV |
| `GET` | `/account` | Premium, текущий лимит файла |
| `POST` | `/storages` | создать приватный канал: `name`, необязательное `description` |
| `GET` | `/storages` | список хранилищ: наш id, название, описание, есть ли фото, `available` |
| `GET` | `/storages/{id}` | одно хранилище + число файлов и общий объём |
| `PATCH` | `/storages/{id}` | изменить название и/или описание (пишется в TG) |
| `PUT` / `DELETE` | `/storages/{id}/photo` | поставить или убрать фото (только изображение, проверки §8) |
| `GET` | `/storages/{id}/photo` | фото потоком из TG |
| `POST` | `/folders` | создать папку (`path`) |
| `GET` | `/folders?path=` | содержимое папки: подпапки и файлы |
| `DELETE` | `/folders?path=` | удалить папку рекурсивно |
| `POST` | `/uploads?path=...` + тело файла | загрузка с устройства |
| `POST` | `/uploads/from-url` | загрузка по ссылке |
| `POST` | `/uploads/batch` | до 100 загрузок по ссылкам одним запросом, ошибка одной не мешает остальным |
| `GET` | `/tasks?batch_id=` | задачи и общий прогресс пачки |
| `GET` | `/tasks/{id}` | прогресс задачи (стадия, процент, скорость, ETA, номер в очереди) |
| `POST` | `/tasks/{id}/cancel` | отмена задачи в очереди или в работе |
| `POST` | `/tasks/{id}/priority` | смена приоритета задачи в очереди |
| `POST` | `/tasks/{id}/retry` | повтор упавшей загрузки по ссылке |
| `GET` | `/files/{uuid}` | все метаданные файла |
| `GET` | `/files/by-path?path=` | метаданные по пути |
| `GET` | `/files/{uuid}/download` | скачать потоком из TG, с поддержкой `Range` (перемотка видео) |
| `DELETE` | `/files/{uuid}` | удалить из TG и БД |

## 11a. Сотни загрузок разом

Очереди Celery на RabbitMQ (подробно — `docs/background-tasks.md`):

- три очереди с приоритетом `low/normal/high`: `uploads.download`, `uploads.prepare` (проверка) и `uploads.telegram` (выгрузка в TG),
  у каждой свой воркер и своё число потоков; ждущие видят `waiting.reason = queue:<очередь>` и `queue_position`;
- место на диске резервируется до приёма файла, нехватка → `507`; активных задач не больше `UPLOAD_MAX_ACTIVE_TASKS` → `429`;
- FloodWait ставит на паузу всю выгрузку в TG, задачи продолжают после паузы; сетевые сбои TG и недоступный ClamAV повторяются с растущей паузой;
- в один путь одновременно идёт только одна загрузка (блокировка пути в Redis), `keep_both` резервирует свободное имя сразу;
- куски большого файла уходят в TG параллельно (`TELEGRAM_UPLOAD_WORKERS`).

`worker-telegram` работает одной репликой со своей сессией Telethon: пауза FloodWait общая на процесс.

## 12. Тесты

- К каждому новому функционалу — тесты. Чем больше, тем лучше.
- pytest: unit / integration / api. Telegram и ClamAV — фейки, Postgres, Redis и RabbitMQ — настоящие (testcontainers или `make test-docker`), воркеры Celery — настоящие в потоках. Нагрузка — locust (`make load`).
- Обязательно покрыть: правила пути, все режимы `on_conflict`, лимиты 2/4 ГБ, фото > 10 МБ при `send_as=media`,
  отказ не-медиа и подмены расширения, SSRF (private IP, редиректы, DNS rebinding), ClamAV (заражён / недоступен),
  стадии и проценты прогресса, вебхук с подписью, рекурсивное удаление папки, инициализацию хранилищ из `.env`
  (идемпотентность, отказ публичному каналу), FloodWait.

## 13. Правила разработки

- Документация в `docs/`, `README.md` и `CLAUDE.md` обновляются вместе с кодом.
- Новые запросы к БД — с индексами.
- Каждое изменение коммитится, **push не делается**.
